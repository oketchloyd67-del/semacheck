Developer docs

Authentication, requests, responses, quotas, webhooks, and the widget guide.

Authentication

API customers send a sk_live_ secret key as a bearer token. The dashboard issues keys, one per account. Never log or store the raw key.

Authorization: Bearer sk_live_YOUR_API_KEY_HERE

Check

POST /v1/check. Returns a verdict, confidence, and reasons.

POST /v1/check Authorization: Bearer sk_live_... Content-Type: application/json { "checkType": "phone", "subject": "254712345678" }
{ "requestId": "abc123…", "cached": false, "verdict": "reported", "confidence": 72, "displayVerdict": "Reported", "reasons": [ { "code": "reported", "label": "Some reports link this subject to a scam.", "source": "reports" }, { "code": "web_result", "label": "Web results raise caution.", "source": "external" } ], "subject": "254712345678", "meta": { "plan": "Free", "planCode": "free" } }

Verdict values

reported Reported — proof points exist.
caution Caution — something is off.
registered Registered — matches a known public record.
unverified Unverified — nothing yet says either way.

Webhooks

The Growth plan sends signed POST requests when a watched subject changes verdict.

POST https://your-server.com/webhooks X-SemaCheck-Event: subject.verdict_changed X-SemaCheck-Signature: t=1760000000,v1=9f2b…e41c { "event": "subject.verdict_changed", "created_at": "2026-10-04T11:02:10Z", "data": { "type": "phone", "value": "254712345678", "previous_verdict": "unverified", "verdict": "reported", "confidence": 72 } }
